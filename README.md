# TAPP-Con
Constrained Tensor Multiplication Plugin

The simulation of strongly correlated quantum systems—such as conjugated polymers (e.g., trans-polyacetylene) and charge-transfer insulators—relies heavily on tensor network methods like Matrix Product States (MPS) and Matrix Product Operators (MPO) [1]. A critical bottleneck in these simulations is the exponential scaling of matrix dimensions during tensor contraction, specifically matrix multiplication [2]. This project proposes the development of an open-source plugin that implements constrained matrix multiplication for tensor networks, optimizing the contraction process by embedding discrete linear constraints directly into the tensor structure.

In quantum chemistry and condensed matter physics, tensor networks represent complex many-body wavefunctions. The core operation in these methods is tensor contraction, which mathematically reduces to matrix multiplication [3]. As the system size or the required accuracy (bond dimension $\chi$) increases, the computational cost of these matrix multiplications grows exponentially [4].

Recent research has introduced "constrained tensor networks," which embed arbitrary linear constraints—such as $U(1)$ symmetry or physical particle number conservation—directly into the tensor network [5].

> **The Integration Gap:** Existing high-performance tensor contraction libraries and quantum virtual machines (like TNQVM) lack native, optimized support for these constrained operations. This leads to inefficient memory allocations and suboptimal execution when simulating strongly correlated materials [6].

We propose building an open-source C++ plugin that implements constrained matrix multiplication for tensor networks. The plugin will adhere to the **Tensor Algebra Processing Primitives (TAPP)** standard, ensuring seamless interoperability with major tensor libraries and quantum simulators [7].

* **Constraint Embedding:** Allows users to define discrete linear constraints that dictate the block-sparse structure of the tensors [5].
* **Optimized Block-Sparse GEMM:** A highly optimized General Matrix Multiply (GEMM) routine specifically tailored for the dense sub-blocks generated by constrained tensor networks.
* **TAPP Standard Interface:** Conforms to the TAPP C-API, functioning as an interchangeable backend for higher-level frameworks like TNQVM or ITensor [7, 8].
* **Hardware Acceleration:** Native GPU acceleration (via cuBLAS/cuTENSOR) with an automatic fallback to optimized CPU BLAS (e.g., OpenBLAS, Intel MKL).

The primary application domain for this plugin is **strongly correlated molecular quantum mechanics**.

| Use Case | Description | Impact |
| --- | --- | --- |
| **Conjugated Polymers** | Simulating electronic structures and excited states of long-chain polymers like trans-polyacetylene [1]. | Bypasses the scaling failures of traditional Coupled Cluster methods. |
| **Quantum Chemistry** | Optimizing Hamiltonian representations as MPOs for complex organic molecules [9]. | Drastically reduces computational overhead in Density Matrix Renormalization Group (DMRG) loops. |


The plugin will be designed as a modular, standalone library divided into three layers:

```
┌────────────────────────────────────────────────────────┐
│             TAPP C-API Frontend Interface              │
└───────────────────────────┬────────────────────────────┘
                            ▼
┌────────────────────────────────────────────────────────┐
│     Constraint Engine (Symmetry & Block Parsing)       │
└───────────────────────────┬────────────────────────────┘
                            ▼
┌────────────────────────────────────────────────────────┐
│  Execution Backend (Hardware Accelerated Block GEMM)   │
└────────────────────────────────────────────────────────┘

```

1. **Frontend Interface:** A C-API compliant with the TAPP specification, allowing external applications to define tensor descriptors, constraints, and contraction operations [7].
2. **Constraint Engine:** A module that analyzes the provided linear constraints to map out the optimal block-sparse structure and contraction path before memory allocation.
3. **Execution Backend:** The computational core executing the block-sparse matrix multiplication, utilizing hardware-specific optimizations.

### TNQVM Integration Ecosystem

The plugin will be wrapped as a high-performance backend for the Tensor Network Quantum Virtual Machine (TNQVM). Similar to the recent integration of Julia-ITensors into TNQVM, this plugin provides a native C++ alternative specifically optimized for constrained systems [8].
